# Intake questions

Ask these in one message, grouped as below, numbered so the user can answer by number. Offer the default in brackets for anything that has one. Skip a question the user already answered in their request.

## Format and framing

1. Should the frame show the whole app window for context first and then push in on the area being redesigned? [yes: open on the full window, push in, pull back out at the end]
2. Crop: once pushed in, frame just the redesigned panel, or keep the full window? [just the panel, with a little margin]
3. Background behind the app window? [dark gray, a few steps lighter than the app's darkest surface, so the window edge reads]
4. Window frame: border and shadow around the app? [1px border in the same color as the app's own divider lines, soft drop shadow, rounded corners]
5. Target length or pace? [about 2 to 3 seconds per change plus 1.5s intro and 3s outro]
6. Loop, and any final MP4 size requirements (16:9 for social, native, 2x)? [loop in preview; MP4 at native size, 60fps]

## Content

7. The two screenshots differ in places beyond the redesign. Which version of the shared content should both states use? (titles, file names, data)
8. Is the surrounding content relevant to the story (chat transcript, file names, tab names, page titles)? If not, what should it say? [rewrite it to match what the redesigned screen shows]
9. Should any content in the before shot be removed so it does not distract? (stray chips, leftover messages, debug text)
10. Rebuild static complex content (charts, slides, documents) as images cut from the screenshot, or as live markup? [images; only live where it moves or changes]

## Per improvement

For each numbered improvement the user listed, ask only what is ambiguous, for example:

11. How does element X get from its old place to its new one: move, fade, or morph in place?
12. Where did removed controls go? (Every removed control needs a home or a reason.) Should the video point that out with a callout? [yes, a short "moved here" callout]
13. Does any new behavior need a demonstration, such as a hover state or an expanding menu, with a cursor? [demonstrate hover with a cursor when the change is about discoverability]
14. Order: as listed, or grouped by screen region? [grouped by region: finish one area before moving to the next]

## Copy and assets

15. Note copy: condense your reasons into short handwritten notes, or do you have exact wording? [condense; keep each note under about 7 words]
16. Typeface: do you have the product's font files? [use them if supplied; otherwise the closest system or Google font]
17. Icons: can I cut icons from the screenshots, or do you have SVGs? [cut from screenshots with transparency]
18. Placeholder content such as sources, numbers or names: may I write believable placeholders, or will you supply real ones? [placeholders, flagged clearly on delivery]
